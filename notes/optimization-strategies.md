# StrataSolidity — Low-hanging optimization strategies

> Source: pipeline timing experiment (May 2026) using `bench/bench_timing.sh`.
> Baseline numbers from `bench/timing_results.csv` (b1..b7, SMT timeout 30s).
> Aggregate: frontend ~40%, verify ~59%, IR stages combined ~1%.
>
> Grounding: read `Tools/Solidity/src/solast.py`,
> `Strata/Strata/Languages/Core/Verifier.lean`,
> `Strata/Strata/DL/Imperative/SMTUtils.lean` before drafting this list.

Key code findings:

- **Frontend** (`solast.py`): one-shot Python CLI; each call pays
  interpreter cold-start (~80–120 ms), then forks `solc --standard-json`,
  parses JSON, walks the AST, dumps Ion. No caching, no batching, no daemon.
- **Verify** (`Verifier.lean` + `SMTUtils.lean`): obligations are processed
  by a sequential `for ... in E.deferred` loop. Each obligation calls
  `runSolver` which is `IO.Process.output { cmd := "z3", args := [filename] }`
  — a **fresh z3 process per obligation**, no incremental push/pop, no
  concurrency. `removeIrrelevantAxioms` defaults to `false` in our
  pipeline (only Laurel test wrapper enables it). Per-obligation timeout
  is `-T:30`, no global budget.

Below, ordered by ROI per engineering hour. Marked **🥝 low-hanging**
(≤1 day, low risk), **🍎 medium** (≤1 week), **🍐 stretch**
(architectural). Effort/gain are estimates from code reading, not
measurements.

## Frontend (~100–200 ms fixed, ~40% of small-file budget)

1. **🥝 Cache-by-content-hash** — keep a
   `~/.cache/strata-solidity/<sha256(.sol + dialect_version)>.solidity.st.ion`.
   The whole frontend stage becomes a hit-or-miss `stat`. Re-running the
   same file costs ~0 ms.

2. **🥝 Skip the dialect file load on every invocation** —
   `solidity_dialect(args.dialect)` reads and parses
   `Solidity.dialect.st.ion` from disk every run. Cache it as a Python
   module-level singleton when the path is unchanged, or embed a
   compiled-once Python representation generated by `gen_dialect()` and
   pickle it.

3. **🥝 Avoid the project-root walk for single-file mode** —
   `invoke_solc` walks up 10 dirs looking for
   `foundry.toml`/`hardhat.config.*`/`package.json`/`remappings.txt`.
   For our bench corpus none exist, so we always do 10 `os.exists`
   calls. Add a `--no-project-detect` fast path for CLI use.

4. **🥝 Drop unused solc outputs** —
   `outputSelection: {"*": {"": ["ast"]}}` is already minimal, but add
   `"settings.optimizer.enabled": false` and `"settings.modelChecker": {}`
   explicitly so solc doesn't initialize anything beyond the parser.
   Also pass `--stop-after parsing` if available on the installed solc
   — turns `solc` into a parse-only run.

5. **🥝 Use `--metadata-hash=none` and `--no-cbor-metadata`** — small
   but free wins; AST-only runs already shouldn't generate metadata,
   but explicit flags shave bytes from the output JSON we then parse.

6. **🍎 Persistent solc daemon (`solc --lsp` or `--standard-json`
   server mode)** — each invocation eats `solc` startup (which is
   significant). Modern solc supports an LSP mode. Even a simple
   wrapper (long-running solc that reads JSON requests on stdin)
   eliminates the ~50–80 ms per call.

7. **🍎 Persistent Python frontend (`solast` daemon)** — the Lean
   binary spawns Python every run. A long-lived `solast --serve` over
   a Unix socket (or stdin/stdout JSON-RPC) collapses Python
   interpreter startup, dialect load, and import time to a one-time
   cost. Same idea as `pylsp` or `mypy --daemon`.

8. **🍎 Replace `amazon.ion.simpleion` with `ion-c` Python bindings**
   — `simpleion` is pure Python and slow. The C extension is 5–20×
   faster on dump for typical sizes. Drop-in replacement.

9. **🍎 Stream the AST conversion** — `Converter.convert_source_unit`
   walks the entire JSON AST then `prog.to_ion()` re-walks the strata
   IR to emit Ion. For larger files, fuse those passes (emit Ion as
   we walk).

10. **🍐 Port the frontend to Lean** — solc itself isn't replaceable,
    but `solast.py` (JSON → Ion via the dialect) could become a Lean
    module that calls `solc --standard-json` directly. Eliminates
    Python entirely. Big change, high cleanup, durable speedup.

11. **🍐 Skip JSON entirely** — solc supports CBOR-ish output and
    there's been work on a binary AST. Avoiding JSON parse +
    dialect-driven re-encode would chop a meaningful slice. Worth
    tracking solc upstream rather than building.

12. **🥝 Warm path for the dev loop** — wire `lake build` so the
    binary auto-runs `solast` once at start to prime `__pycache__`
    and any `.pyc` files. Cheap, eliminates first-run penalty in
    benches.

## Verify (~60% of budget on b6/b7, scales with obligation count)

13. **🥝 Parallelize obligations across cores** —
    `verifySingleEnv`'s `for obligation in E.deferred do` is
    embarrassingly parallel: each obligation has its own SMT file and
    z3 process. Replace with `IO.asTask` + `IO.wait` over `obligation`.
    On b7 (26 obligations) on a typical 8-core dev machine, this alone
    should drop verify from ~470 ms toward ~80–120 ms (limited by the
    slowest single obligation). **Highest expected ROI in the whole
    list.**

14. **🥝 Reuse the z3 process via `(check-sat)` after `(push)`** —
    instead of one `z3 file.smt2` per obligation, send all obligations
    from a single function as `(push) ... (check-sat) ... (pop)` to
    one z3 process over stdin. Same proofs, but you pay z3 startup
    once per function instead of per obligation. Many SMT-LIB clients
    (boogie, dafny) work this way.

15. **🥝 Turn on `removeIrrelevantAxioms` for Solidity** — already
    plumbed in (`VerifyOptions.removeIrrelevantAxioms`), but defaults
    to `false` in our pipeline. The Laurel translator wrapper sets it
    `true` and the comment says it avoids polluting simple assertions
    with heap axioms. Flip the default in `StrataSolidityMain.lean`,
    measure b6/b7, ship.

16. **🥝 Tune the prelude** — `getSolverPrelude` for z3 sets only
    `smt.mbqi=false` and `auto_config=false`. For the kinds of VCs we
    generate (mostly QF_LIA + select/store from mappings), a stronger
    prelude helps: `smt.arith.solver=2` (arithmetic-as-LRA),
    `model.compact=true`, `combined_solver.solver2_unknown=0` (skip
    second-tier solver on unknown). Each is one line in
    `getSolverPrelude` and measurable by re-running our bench.

17. **🥝 Lower per-obligation timeout, raise per-run budget** —
    current `solverTimeout` is per-obligation. With the b6 outlier
    (899 s in `bench/results.csv`) one obligation ate the whole bench.
    Set per-obligation to e.g. 5 s and add a global bench-level kill.
    Forces hard-cases to fail fast and surface for separate triage.

18. **🥝 Skip SMT for `pass`-via-preprocess obligations** —
    `preprocessObligation` already short-circuits some via partial
    eval (`maybeResult.isSome`). Make sure those don't even open the
    temp SMT file (currently the file is created in
    `getObligationResult` after the short-circuit, so this may already
    be fine — verify, then document).

19. **🥝 Stream SMT to z3 over stdin instead of writing a file** —
    `runSolver` passes `args := [filename]`, which means write-to-disk
    + z3 reads-from-disk + we keep an unused file. Pipe over stdin
    (`stdin := .piped`) and skip the FS round-trip. Tiny per-call
    save (a few ms × N obligations) but free and removes filesystem
    noise from the timing.

20. **🥝 Pool the temp dir per process, not per run** — currently
    `IO.FS.withTempDir` per verifier call (or
    `/tmp/strata-pipeline-smt` only with `--pipeline-json`). Always
    use a fixed per-PID dir to avoid mkdir/rmdir on hot paths.

21. **🍎 Cache obligation results by SMT-script hash** — once the
    encoded SMT script is fixed for an obligation, its outcome is
    deterministic for a given solver+version. Cache
    `sha256(smt_script + solver_version) → outcome` in
    `~/.cache/strata-solidity/smt`. Editing one function's body
    invalidates only that function's obligations.

22. **🍎 Parallelize across functions and within a function** —
    finer-grained: dispatch obligations as soon as their preprocessing
    finishes, with a worker pool. Combined with #13 + #14 this is
    roughly the same as `dafny --cores=N`.

23. **🍎 Z3 tactic specialization** — instead of letting z3 pick its
    strategy, use `(check-sat-using (then simplify solve-eqs smt))`
    for our class of VCs. Boogie/Dafny ship hand-tuned tactics; we
    can crib the bv/array-free LIA one.

24. **🍎 Switch default solver to cvc5 for scalar-only obligations**
    — code already supports cvc5. Some obligations are faster on cvc5
    than z3; a "race two solvers, return first answer" wrapper (à la
    SMT-COMP "portfolio") often wins for free at the cost of a second
    core.

25. **🍎 Memoize axiom encoding within a run** —
    `Strata.SMT.Encoder.encodeCore` is invoked per obligation with
    the same `ctx`. The shared assumption-prelude (axioms, type
    declarations, map theory) is identical across obligations from
    the same function. Cache the encoded prelude string and prepend
    per obligation rather than re-running the encoder.

26. **🍎 Drop unused declarations per obligation** — somewhat related
    to `removeIrrelevantAxioms` but stricter: a per-obligation "used
    symbols" pass that strips declarations the obligation can't
    reference. Smaller SMT scripts, smaller solver search space.

27. **🍐 Incremental verification for IDE/dev loop** — when only one
    function changes, only its obligations need re-checking. Hash-key
    the function body + its referenced axioms; reuse cached results
    otherwise. Closes the gap with `dafny --cores --incremental`.

28. **🍐 Replace per-call `IO.Process.output` with a long-lived
    solver pool** — combines #13 + #14 + #19: a small pool of N
    persistent z3 processes, each fed problems over stdin with
    `(reset)` between obligations (or `(push)/(pop)` if we structure
    the script). Eliminates process startup × obligations.

29. **🍐 Profile-guided VC pruning** — instrument which axioms each
    obligation actually consumes (z3 `proof` mode, even on a sample).
    Permanently elide axioms that no proof uses. One-time analysis
    cost, permanent runtime savings.

## Cross-cutting / tooling

30. **🥝 Make `--timing` always-on (default off only for
    `--sarif`/`--json`)** — currently opt-in. Cheap, gives every CI
    run a stage breakdown so we can spot regressions automatically.

31. **🥝 Add per-obligation timing in the verifier** —
    `getObligationResult` doesn't time individual SMT calls. A
    `IO.monoMsNow` around `runSolver` would tell us **which**
    obligations dominate. Right now we know "verify is 470 ms" but
    not whether 5 ms × 26 obs or 200 ms × 1 + 10 ms × 25.

32. **🥝 Bench-mode flag that disables logging/dbg_trace** —
    `dbg_trace` calls in `verifySingleEnv` and `preprocessObligation`
    fire on `verbose >= .normal`. Confirm they're truly off for
    `verbose := .quiet` (they are, but the format strings are still
    constructed in some paths — check whether Lean's `if`
    short-circuits before `f!"..."`).

33. **🥝 Add the `b5_escrow` failure to a separate lane** — it errors
    out and reports 0 obligations, which understates the real
    frontend cost on a successful run. Either fix the underlying
    enum-comparison bug or move it to a separate
    `bench/known_failures/` so the headline numbers reflect the
    working corpus.

34. **🍎 Compile with `-O` aggressive flags / native code for the
    verifier** — Lean 4's `lake build` defaults are reasonable, but
    `LEAN_CC=clang` + `--native` for hot modules (encoder, SMT
    preprocessing) sometimes pays off. Worth a 1-day spike.

35. **🍐 Canonicalize the encoder's output to enable solver-side
    caching** — z3's `(set-option :smt.macro-finder true)` plus z3's
    own scheme-cache only helps if our scripts are byte-identical
    across runs. Our temp filename appears in some `set-info` lines —
    strip it.

## Top-3 if you can fund only a few

1. **#13 parallelize obligations** — biggest expected jump on
   b7-class contracts, low risk, isolated change.
2. **#15 enable `removeIrrelevantAxioms` by default** — one-line
   diff, already battle-tested in Laurel tests, immediate effect.
3. **#1 frontend content-hash cache** — wipes the entire frontend
   cost off the second-and-onward runs, which is most of the dev
   loop. One-time implementation, no semantic risk.

If you also fund a medium-effort item: **#14 z3 push/pop within a
function** — likely doubles the win from #13 because parallelism
shifts the bottleneck to z3-startup, which #14 then dissolves.
